# datatables-factory — audit de `src/`

Périmètre : les 25 fichiers CoffeeScript de `src/` (3 080 lignes), à l'état du
commit `a92fa67`. · Couverture : **25/25 fichiers lus intégralement**.
Le Ruby (`lib/`), les specs et `dist/` n'ont été ouverts que pour établir
l'*accessibilité* d'un défaut de `src/` ou son absence de couverture — ils ne
sont pas audités ici.

**Sémantiques vérifiées cette session** (aucune affirmation ci-dessous ne repose
sur la mémoire) :

- `return false` dans un gestionnaire jQuery ⇒ `stopPropagation()` : les
  gestionnaires du même nœud continuent, ceux d'un ancêtre sont coupés (mesuré,
  jQuery 4.0.0).
- `$('#t').off('xhr.dt')` retire **aussi** `xhr.dt.myapp` et `xhr.dt.dtf-paging` :
  0 survivant sur 3 gestionnaires (mesuré).
- `$.extend(true, {}, {a:[1,2,3]}, {a:[9]})` ⇒ `{a:[9,2,3]}` — fusion des tableaux
  **par index**, fonctions copiées par référence (mesuré).
- `$.parseHTML(str, null)` : supprime `<script>`, **conserve** `onerror` (mesuré).
- `$('<select multiple>').val()` sans sélection ⇒ `[]`, jamais `null` (mesuré).
- `window.matchMedia?('…').matches` compile en chaîne entièrement protégée
  (`typeof … === "function" ? … : void 0`) — pas de déréférencement de `undefined`
  (compilé, CoffeeScript 2).
- Une méthode CoffeeScript terminée par un `for` compile en accumulation dans un
  tableau `results` retourné (compilé).
- Une méthode liée (`=>`) d'une classe dérivée est liée juste après `super()`,
  donc avant le corps du constructeur (compilé sur `date_filter.coffee`).
- `+' '` ⇒ `0`, `isNaN(+' ')` ⇒ `false` (mesuré).
- Reconstruction d'un `TextFilter` sur le même conteneur : **2 wrappers, 3 inputs**
  de même `id`, `BaseFilter#destroy` inexistant (mesuré, jest).
- Rappel debounce déclenché **après** `destroy()` : `run_filter` appelé 1 fois sur
  le filtre démoli (mesuré, jest).
- `load_datatables()` sur une page à deux tables dont la première est malformée :
  `TypeError: Cannot read properties of undefined (reading 'dtf_options')` propagé,
  la seconde table n'est jamais atteinte (mesuré, jest).
- Appui long à deux doigts : 1 menu contextuel s'ouvre **après** que les deux
  doigts ont été relevés (mesuré, jest).

## 1. Correction

**COR-loader.coffee:65** | `load_datatables` itère avec `$.each` sans isolation : une exception dans une table interrompt la boucle et remonte à l'appelant. | **Scénario** : une page porte deux tables ; la première a un attribut `data-dtf-loader` absent ou malformé. `extract_options(...).loader` vaut `undefined`, `new Logger(undefined.dtf_options)` lève. ## 2. Concurrence (durées de vie asynchrones)

Le code est mono-thread : la dimension se lit ici comme « qu'est-ce qui survit à
la destruction de sa cible ».

**CON-base_filter.coffee:162** | `_with_delay` garde son `timer` dans une closure qu'aucun `destroy` n'atteint — ni `SelectBase#destroy`, ni `DateFilter#destroy`, ni `RangeNumberSliderFilter#destroy`. | **Scénario** : avec `filter_delay: 300` (valeur courante), l'utilisateur tape puis navigue dans les 300 ms. Mesuré : le rappel s'exécute **après** `destroy()` et appelle `run_filter` sur le `DatatableFilter` démoli, qui atteint `@instance.columns(...).search(...).draw(false)` sur une API DataTables détruite, puis `save_state` qui replanifie un `setTimeout` que plus personne n'annulera (`datatable_filter.coffee:70` a déjà vidé le sien). | **Correctif** : faire porter le timer par l'instance (`@_delay_timer`) et l'annuler depuis un `destroy` défini sur `BaseFilter`.

**CON-context_menu.coffee:71** | La requête du menu n'est jamais annulée et aucune référence n'est conservée. | **Scénario** : deux clics droits rapprochés sur deux lignes différentes ; les deux réponses arrivent, chacune ferme sur ses propres `render_x`/`render_y`. La réponse la plus lente réécrit le contenu du menu déjà ouvert et le repositionne sur les coordonnées de l'**ancien** clic — le menu affiché n'appartient plus à la ligne pointée. | **Correctif** : conserver le `jqXHR` en variable de module et l'`abort()` en tête de `show`.

## 3. Modèle d'erreur

**ERR-context_menu.coffee:89** | La requête du menu journalise en `console.error` un abandon réseau, exactement le cas que `loader.coffee:32-34` dégrade délibérément en `console.warn`. | **Scénario** : l'utilisateur ouvre un menu contextuel puis navigue aussitôt ; jQuery rapporte `status: 'error'` avec `xhr.status === 0` — le filtre `status == 'abort'` de la ligne 88 ne l'attrape pas (c'est précisément ce que documente le commentaire de `loader.coffee`). Un moniteur RUM comptabilise chaque navigation comme un crash. | **Correctif** : reprendre la règle du loader — `if xhr.status == 0 then console.warn else console.error`.

**ERR-with_check_boxes.coffee:157** | La branche `else` retourne `false` depuis un gestionnaire d'événement DataTables. | **Scénario** : mesuré, `return false` déclenche `preventDefault` + `stopPropagation`. Dès qu'une réponse ne porte pas `records_selected` — le cas normal de toute table à cases à cocher dont le serveur ne compte pas la sélection — l'événement `xhr.dt` cesse de remonter, et tout gestionnaire que l'hôte aurait posé sur un ancêtre (`$(document).on('xhr.dt', …)`) ne s'exécute plus. Les gestionnaires du même nœud, eux, survivent. | **Correctif** : `return` nu au lieu de `return false`.

**ERR-with_buttons.coffee:119** | `_build_ajax_options` et `_loader_load_buttons_callbacks` supposent, sans le documenter ni le vérifier, que `@callbacks['buttons'][nom][phase]` est un tableau. | **Scénario** : un consommateur écrit `@callbacks['buttons']['select_all']['success'] = fn` dans son `before_init` — lecture naturelle du commentaire « a consumer may already have registered ». `(fn or []).concat([callback])` lève `concat is not a function` pendant `loader_load_callbacks`, donc pendant `load()`, donc — cf. `COR-loader.coffee:65` — toutes les tables de la page sont perdues. | **Correctif** : normaliser (`[].concat(entry['success'] or [])`) et documenter le contrat.

## 4. Performance / mémoire / CPU

Aucun de ces points n'est visible sur une table ordinaire ; ils sont classés bas
à dessein et listés parce qu'ils se déclenchent tous sur le **même** chemin chaud
(une frappe dans un filtre = un `xhr.dt` = tout ce qui suit).

**PERF-select_base.coffee:88** | `JSON.stringify(@dropdown_data)` est recalculé à chaque `xhr.dt`, pour chaque filtre select, uniquement pour détecter un changement. | **Scénario** : le serveur renvoie `dt_filter_data_<col>` à chaque réponse (`datatable_filter.coffee:327-331`) ; sur une table à trois selects de plusieurs milliers d'options, chaque frappe dans un champ texte sérialise l'ensemble des trois listes avant de conclure qu'elles n'ont pas changé. | **Correctif** : comparer d'abord la référence du tableau reçu et sa longueur, ne sérialiser qu'en cas d'écart.

**PERF-select_base.coffee:98** | `reload` rappelle `restore_state()` à chaque tirage même quand la signature est inchangée. | **Scénario** : chaque tri, chaque changement de page, chaque frappe dans un autre filtre réémet un `select_plugin.setValue(...)` + `addClass('inuse')` par filtre select — pour tom-select, un ré-affichage complet de l'item. | **Correctif** : rentrer `@restore_state()` dans la branche `signature != @_dropdown_signature`.

**PERF-loader.coffee:342** | Le pipeline ajax clone en profondeur la charge utile deux fois par callback enregistré : une fois dans le callback (`Utils.merge_hash(d, e)`), une fois dans la boucle. | **Scénario** : table à cases à cocher + module debug sur 30 colonnes ⇒ 4 clones récursifs de `data` (30 objets colonne avec leur objet `search` imbriqué, plus les tableaux d'identifiants sélectionnés) avant le `JSON.stringify` de la ligne 39 qui re-sérialise le tout — à chaque requête. | **Correctif** : les callbacks ne rendent que leur delta, fusionné une fois par `Object.assign`.

**PERF-with_logger.coffee:9** | Le message est intégralement interpolé — y compris `name()`, qui concatène trois champs — avant que `Logger#info` ne teste `debug_log`. | **Scénario** : en production, `debug_log` est faux ; chaque frappe construit tout de même deux à trois chaînes jetées par filtre, et `_dt_on_draw` une par filtre et par tirage. | **Correctif** : passer un thunk, ou tester le drapeau au point d'appel.

**PERF-with_check_boxes.coffee:220** | `_add_row_if_checked` fait, par ligne créée, une recherche DataTables par identifiant sur la page courante, chacune déclenchant un événement `select` qui rejoue `update_select_all_ctrl` et ses trois balayages du conteneur. | **Scénario** : hôte dont le serveur rend les cases déjà cochées ; avec `pageLength: 100`, un tirage fait 100 recherches sur 100 lignes plus 300 balayages `input[type=checkbox]`. Non déclenché par l'application de démonstration, qui injecte les cases *après* ce rappel. | **Correctif** : accumuler les identifiants cochés puis un seul `@datatable.rows(ids).select()` depuis `drawCallback` ; dériver `chkbox_checked` de `chkbox_all.filter(':checked')`.

**PERF-context_menu.coffee:24** | `$('#context-menu')` est ré-interrogé 14 fois par ouverture, et les lectures `.width()`/`.height()` (lignes 29-30) suivent les écritures `.css()` (24-25). | **Scénario** : chaque clic droit paie 14 recherches par identifiant sur le document plus un reflow synchrone forcé avant le positionnement — c'est le délai perceptible entre le clic et l'apparition du menu sur une page lourde. | **Correctif** : mettre l'élément en cache en tête de `show` et grouper les lectures avant les écritures.

**PERF-base_filter.coffee:153** | `_skip_key_codes()` alloue un tableau de 4 éléments à chaque appel. | **Scénario** : appelé à chaque frappe depuis `text_filter.coffee:129`, `range_number_filter.coffee:18` et `range_date_filter.coffee:115`. | **Correctif** : constante de module.

## 5. Conception d'API

**API-datatable_filter.coffee:286** (et `:279`, `:71`) | `_bind_datatable` fait `off('xhr.dt')` et `off('stateSaveParams.dt')` — sans espace de noms propre — alors que tout le reste de la bibliothèque a été soigneusement namespacé (`.dtfCheckBoxes`, `.dtfContextMenu`, `.dtf-paging`). | **Scénario** : mesuré, `off('xhr.dt')` retire les trois gestionnaires testés, y compris un `xhr.dt.myapp` posé par l'hôte. Une application qui branche `$('#ma-table').on('xhr.dt.myapp', fn)` avant `load_datatables()` — le motif documenté par DataTables pour capter les événements de pré-initialisation — perd son gestionnaire silencieusement à `preInit`. C'est aussi ce qui force la gymnastique de `loader.coffee:151-157` pour rebrancher `.dtf-paging` après coup. | **Correctif** : `off('xhr.dt.dtfFilter').on('xhr.dt.dtfFilter', …)` — ce qui supprime au passage la contrainte d'ordre du loader.

**API-select_base.coffee:187** | La branche `select2` n'affecte jamais `@select_plugin`, donc `destroy()` (`:77-79`) n'y fait rien. | **Scénario** : une table portant un filtre select2, rechargée en place, laisse le widget select2, ses gestionnaires au niveau document et son conteneur frère `.select2-container` en place ; le nouveau filtre en crée un second. Cumulé avec `COR-base_filter.coffee:51`, chaque rechargement ajoute un widget complet. | **Correctif** : mémoriser la nature du plugin et appeler `@_el(@select_id).select2('destroy')`.

**API-datatable_base.coffee:88** | `destroy()` déréférence `@datatable` sans garde et le met à `null` — un second appel lève. | **Scénario** : un hôte qui appelle `destroy()` sur son `turbo:before-cache` en plus du chemin de rechargement de `Loader.load` obtient `TypeError: Cannot read properties of null (reading 'destroy')`. Même chose si l'initialisation a échoué avant `preInit`. | **Correctif** : `return if !@datatable?` en tête.

**API-select_filter.coffee:15** | `SelectFilter#set` et `SelectMultiFilter#set` écrivent la valeur de recherche et l'état, mais ne touchent pas au widget — contrairement à `TextFilter#set` (`text_filter.coffee:67`). | **Scénario** : un `populate_with` sur une colonne select filtre bien la table, mais la liste déroulante continue d'afficher son libellé par défaut jusqu'au premier `xhr.dt` porteur de `dt_filter_data_<col>`, qui la resynchronise via `reload → restore_state`. Sur un select dont les options ne viennent pas du serveur, l'écart est permanent : la table est filtrée sans que rien ne le montre. | **Correctif** : appeler `@_set_select_value(value)` et poser `inuse` dans `set`, comme le fait le filtre texte.

**API-select_multi_filter.coffee:65** | `_cast_value` appelle `value.join('|')` sans vérifier le type. | **Scénario** : un `populate_with` déclarant une valeur scalaire pour une colonne `multi_select` fait lever `value.join is not a function` dans `_apply_filters`, ce qui interrompt l'application de **tous** les filtres par défaut suivants (la boucle `datatable_filter.coffee:299-307` n'a pas de garde). | **Correctif** : `[].concat(value).join('|')`.

## 6. Sécurité

## Hypothèses vérifiées et écartées

- **`_restrict_touch_selection_to_check_boxes` viserait une classe inexistante.** `select['selector'] = 'td.check_box'` — vérifié dans `lib/datatables_factory/data_column.rb:58-68` : `css_class` inclut `@name.to_s`, donc `check_box`, et il part en `className` de la colonne (`:21`). Le sélecteur est correct.
- **`window.matchMedia?(...).matches` lèverait sur un navigateur sans `matchMedia`.** Compilé : la chaîne entière est protégée par `typeof … === "function" ? … : void 0`. Sans objet.
- **`@_date_select` (méthode liée `=>`) serait lue avant sa liaison** dans le constructeur de `DateFilter`, qui l'utilise à la ligne 17. Compilé : CoffeeScript place `this._date_select = this._date_select.bind(this)` immédiatement après `super(...arguments)`, donc avant le corps. Sans objet.
- **`SelectMultiFilter#_empty_value` lèverait sur `null`.** Mesuré : `$('<select multiple>').val()` rend `[]` et non `null` en jQuery 4 (le comportement historique inverse ne s'applique plus). `value.length` est sûr tant que l'élément existe.
- **La fusion par index de `$.extend(true, …)` corromprait la charge ajax** (`selected` de 3 identifiants écrasé par un de 1). Mesuré que la fusion est bien par index — mais DataTables reconstruit l'objet `data` à chaque tirage (`_fnAjaxParameters`), donc aucune contamination inter-tirages, et les deux callbacks enregistrés produisent le même tableau. Pas de bug, seulement le coût listé en `PERF-loader.coffee:342`.
- **`@columns` / `@buttons` divergeraient de `@dt_options` après les clones profonds.** Ils divergent effectivement en identité, mais `_add_callback` mute les boutons pendant `before_init`, c'est-à-dire **avant** le premier `Utils.merge_hash` de `loader_load_callbacks` ; et `$.extend(true, …)` copie les fonctions par référence (mesuré). Les `action` sont donc bien présentes dans les deux tableaux.
- **`destroy()` laisserait fuir l'instance via les gestionnaires `preInit.dt.dtf` / `xhr.dt.dtf-paging` non retirés.** Ils ne sont effectivement pas retirés, mais `init_datatable` fait `off` avant `on`, donc ils ne s'accumulent pas ; et jQuery 3+ stocke les données d'événement sur un expando de l'élément lui-même, si bien qu'un nœud détaché puis collecté libère la closure. Asymétrie cosmétique, pas une fuite.
- **`$.parseHTML(result, null)` exécuterait les scripts** de la réponse du menu. Mesuré : `keepScripts` vaut `false` par défaut, les `<script>` sont écartés. Le commentaire du code est exact ; le risque résiduel est celui des attributs `on*`, retenu en `SEC-context_menu.coffee:79`.
- **Le `stopPropagation` du clic sur la case « tout sélectionner » ne préviendrait pas le double basculement** avec le gestionnaire délégué du `th`. jQuery évalue `isPropagationStopped()` entre les niveaux de sa file de délégation, donc le niveau `th` est bien coupé. Le mécanisme est correct.
- **Pollution de prototype via `column_id: "__proto__"`** dans `loaded_filters` / `_filter_state`. Les clés viennent de la configuration émise par le serveur, pas d'une entrée utilisateur : un attaquant qui les contrôle contrôle déjà la page. Durcissement possible (`Object.create(null)`), pas une faille. Par ailleurs `$.extend` profond ignore `__proto__` depuis jQuery 3.4 et le plancher déclaré est `>=3.6.0` (`package.json:31`).
- **`dist/js/datatables-factory.js` serait désynchronisé de `src/`.** Vérifié par marqueurs de chaînes propres au code le plus récent (`dtf-paging`, `pointer: coarse`, `td.check_box`, `selected_count_label`, `Saved page is past the last row`, `falling back to plain inputs`, `dtf-filter-icon`, `filter_reset_button_class`) : les huit sont présents dans le bundle. L'arbre de travail est propre.
